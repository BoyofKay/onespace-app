# OneSpace website — https://onespace.live

The public website of OneSpace. Tagline: **Two of Us. One Space.** English at `/page.html`, Arabic at `/ar/page.html`, Spanish at `/es/page.html`, French at `/fr/page.html`, and German at `/de/page.html`. All languages reuse the same full site layout and media. Served free by GitHub Pages on the custom domain **onespace.live** (`CNAME`).

## Public URLs and legacy compatibility

The canonical site routes have no `.html` extension: `/privacy/`, `/terms/`, `/delete-account/`, `/faq/`, `/features/`, `/guides/`, `/tutorials/`, `/join/`, and their `/ar/`, `/es/`, `/fr/`, and `/de/` equivalents. GitHub Pages serves each path from its generated `<slug>/index.html`.

All published .html URLs remain as redirects to clean URLs, retaining campaign query parameters, Founder partner invitations (`?invite=`), email confirmation fragments (`#t=`), unsubscribe tokens (`#u=`) and article section anchors. The original `.html` output is intentionally retained in source/CI as an internal compatibility target; external docs, store listings, FAQs and emails should link to clean routes. The sitemap and hreflang/SEO canonical links are generated for clean routes only.

For any new page, add it to `PAGES` in `build.py`; `content/pretty_routes.py` handles all five locales and old-link bridging. Confirm and unsubscribe pages remain `noindex` in both legacy and clean forms. Run the standard website quality workflow before deployment.

## How it is built
Every page is generated by **`build.py`** from one design system. Edit `build.py`, run `python3 build.py` (needs `beautifulsoup4`), commit the generated files. CI fails if the HTML was not regenerated.

| File | What it is |
|---|---|
| `build.py` | Original English/Arabic website, navigation, shared layout, SEO tags, sitemap, robots, llms.txt, generated locale siblings |
| `content/deep_pages.py` | The 7 feature deep pages (problem → steps → details → before/after → FAQ) and the comparison table |
| `content/legal.json` | Privacy policy and terms (EN/AR), kept in step with the app |
| `assets/os.css`, `assets/os.js` | The only stylesheet and script: menu, language, theme switcher, demo tabs, forms, analytics events, confirmation/unsubscribe pages, admin dashboard |
| `assets/ar.js` | Generated Arabic strings — don't edit by hand |
| `content/full_localization.py` | Source-equivalent Spanish/French/German pages using the original screenshots, phone walkthrough, theme switcher, forms and analytics |
| `content/locale_editorial.py` | Human-authored Spanish/French/German terminology and marketing copy polish |
| `content/translations/` | Versioned multilingual translation catalogues (no live translation calls) |
| `assets/app/` | Real app screens and clips of the fictional demo couple (Adam & Lina), imported by `tools/import_screens.py` from the `app-screens` branch |
| `assets/press/` | Store and social images, rendered by `tools/render_press.py` (previews in `assets/press/preview/`) |
| `tests/check_site.py` | CI: one H1, descriptions, alt text, links, source-equivalent visuals/interactions and anchors (EN/AR/ES/FR/DE), sitemap, redirects, forbidden claims |

## Founder Members waitlist
- The first **500 people** who confirm their email are Founder Members, on their own or as a couple (rules of 22 Nov 2026). **No Founder number is ever shown or emailed.**
- Sign-up → confirmation email (Resend, from `founders@onespace.live`) → `/confirm/` confirms membership and gives the partner invite link (`/join/?invite=…`).
- Data: Supabase project **OneSpace Production**, `private.founder_*` tables (service role only).
- The backend source (SQL + Edge Functions) lives in the **private** app repository `BoyofKay/OneSpace` under `supabase/founders/` (moved out of this public repository on 26 Nov 2026).
- Invite waves, nudges and surveys are run from the private Command Center repository `BoyofKay/OneSpace-Command`.

## Analytics and SEO
- GoatCounter (`onespace`), cookieless. Only the page path is counted (no query string or #fragment). Events are fixed names (`cta/*`, `founders/*`, `demo/*`, `theme/*`, `lang/*`, `outbound/*`) — never form values. Live check: Actions › `analytics-check`.
- Canonical + reciprocal hreflang (en, ar, es, fr, de, x-default) on every page, sitemap covering all five languages, Organization/WebSite/MobileApplication/FAQPage/Article structured data, `llms.txt`, IndexNow ping after every publish (Actions › `indexnow`).

## Translation maintenance
- Follow the internationalization policy below. All ES/FR/DE pages reuse the original full English HTML, not separate mini-landing pages.
- Keep the language catalogues and editorial glossary updated after English copy changes, run `python3 build.py`, then `python3 tests/check_site.py` and `node --check assets/os.js`.
- Founder confirmation emails are currently in English/Arabic only; the translated forms state this clearly.

## Rules for content
- Only the fictional demo couple appears in screens. Never publish real screenshots or personal data.
- Global audience: no country-specific places, currencies, holidays or platforms.
- Don't advertise retired or hidden features: automatic love gestures (D1), voice commands (D55). CI blocks the phrases.
- Founder benefits are not defined yet — "announced before any pricing". No invented testimonials or numbers.

## Workflows
`site-check` (every PR) · `indexnow` (after publishing) · `analytics-check` and `founders-e2e` (manual live checks) · `app-screens` (screenshot robot, runs the app on an emulator).

## Internationalization policy (moved here from docs/INTERNATIONALIZATION.md on 26 Nov 2026)

### Full visual and functional parity
- English is the source layout. **Arabic, Spanish, French and German reuse the original website experience.** ES/FR/DE are generated from the complete English HTML DOM in `content/full_localization.py`, not simplified independent landing pages.
- The same app screenshots (currently English/Arabic images), phone frames, interactive walkthroughs, theme controls, comparison tables, guides, legal and support pages, Founder registration, privacy protections, and product sections are retained. **Do not invent translated app screenshots** when only English/Arabic screenshots exist.
- Every page in `PAGES` gets ES/FR/DE counterparts; confirm and unsubscribe pages also exist in all languages and stay `noindex`.
- Original `assets/os.js`, `assets/os.css`, GoatCounter and Founder Supabase functions are shared. Dynamic form and copy feedback is localized via `SITE_MESSAGES` and `FORM_MESSAGES`.

### Translation approach
- Committed language catalogs: `content/translations/es.json`, `fr.json`, `de.json`. Source inventory: `source_catalog.json`.
- English phrases are mapped to translated text nodes and user-facing attributes while preserving all HTML structure, links, event data attributes, media and forms.
- `content/locale_editorial.py` provides cumulative human-authored editorial corrections to high-visibility marketing, navigation, product benefits, support, privacy headlines and tutorials in each language. Review all additions before publishing. `GLOSSARY` handles core app terminology and privacy labels.
- New missing translations make the build **fail**; they do not silently fall back to English. Rebuilds do not call any translation service.
- For future source-copy changes: regenerate English source; run the one-time `scripts/translate_full_site.py` to populate **new** missing keys, review changed language strings, then build. This script translates *public marketing copy only* and is not used in production.
- Style: Spanish broadly understandable, warm and clear; French natural, conversational and polished; German friendly for product marketing, precise for support/privacy language.
- Review proper names, software terms, quantitative claims, privacy and legal wording before each release. English remains the original reference for interpretation of legal terms. Full long-form native-speaker proofreading (especially privacy and terms) is still an outstanding QA milestone; machine-assisted coverage alone must never be described as native-certified.

### SEO, analytics and Founder limitations
- Canonical URLs, reciprocal `hreflang` and XML sitemap cover every indexable page across en/ar/es/fr/de. `x-default` remains English. IndexNow and Google Search Console submissions use the same sitemap.
- GoatCounter continues tracking localized page paths; UTM source, medium and campaign are preserved when switching languages, without sending email/token query strings to GoatCounter.
- The Founder backend currently sends English/Arabic transactional emails only. Localized Founder forms disclose this rather than falsely promising translations of those emails. Email preference is set to English unless the user explicitly selects Arabic.
- Never claim store listings or automatic Counters updates that do not exist in the app.

### QA gate
```sh
python3 -m pip install beautifulsoup4==4.15.0
python3 build.py
python3 tests/check_site.py
node --check assets/os.js
node --check assets/ar.js
```
The site test checks localized links, anchors, metadata, sitemap, privacy and identical counts of screenshots, media, forms, theme selectors, interactive demo components and tracking markers for every translated page.

### Locale-specific UI and brand guidance
- Preserve the original OneSpace design and use compact, natural CTAs instead of stretching navigation for literal long translations. Mobile navigation begins at the language-safe responsive breakpoint.
- Horizontal screenshot/theme rails use OneSpace-colored accessible scrollbars. Do not replace the real app images with generated translations of screenshots.
- The Google Play and App Store cards are **availability previews**, not live download links. Their recognizable in-page platform marks are not official approved download badges. Replace with the officially supplied localized badges and verified store links only once the relevant store listing is available and brand terms permit use.
- Run Chromium browser responsive checks (script `scripts/check_locale_layout.mjs`) at phone, tablet and desktop sizes when adjusting navigation, language copy or store cards.
- For German marketing, address a couple as **ihr/euch** and an individual as **du/dein**; avoid unexplained switches to Sie. For French use **vous** consistently; for Spanish use broadly understood, natural language and distinguish singular visitor versus couple.
- Do not localize proper brand names such as OneSpace, App Store, Google Play, OpenStreetMap, or app navigation identifiers into unrelated words.

### Long-form editorial review (November 2026)
- Translated legal, FAQ, guide and account-deletion copy is maintained in separate source-keyed review files: `locale_legal_review.py`, `locale_faq_review.py`, and `locale_guides_review.py`.
- Privacy and terms pass: rewrote consent, tracking, notifications, retention, account ownership, advertising, service providers, and deletion descriptions without altering legal durations or product permissions.
- Corrected a **critical broken negation** caused by nested bold markup in the "We do **not** collect" privacy clause. The generator now constructs complete localized sentences in each language.
- FAQ: questions and answers were edited for natural ES/FR/DE usage while preserving Founder, calendar, privacy, notification and iPhone availability details.
- Guides: reviewed actual bullet-point advice, not just introductory headings. Tone is warm, clear and practical; calendar/counter actions remain user-controlled where applicable.
- The localized instructions show today's real **English mobile menu labels** alongside translated explanations. Website language support must not be misrepresented as mobile app UI support.
- Run `python3 tests/check_locale_editorial.py` after a full build; it validates source phrase coverage, critical legal negatives, retention numbers, FAQ completeness, and account-deletion instructions.
- Still outstanding before calling the site *professionally native-certified*: independent native-speaker line editing for all remaining pages, a jurisdiction-qualified legal review of privacy/terms, and confirmation that English policy claims precisely match production app and backend behavior. Automated coverage checks do not substitute for those reviews.
